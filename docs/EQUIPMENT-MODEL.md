# Модель оборудования: категория + тип (проект)

Статус: **проект, требует подтверждения**. Ниже — как устроено сейчас, что
предлагается и как переносить существующие данные.

## 1. Как сейчас

* `equipment.type` — ключ из справочника `equipment_types` (51 запись:
  `key`, `display_name`, `letter`, `sort_order`). Примеры: `v_500` → «В-500»,
  `r_220` → «Разъединитель 220 кВ», `tt_500` → «ТТ-500», `MO` → «Мачта освещения».
* В справочнике смешаны **класс** (выключатель/разъединитель/ОПН) и
  **напряжение** (500/220/110/35) — то есть это уже почти «категория».
* Фотография выбирается **жёстко в коде** по `type`
  (`EquipmentCardController.createEquipmentImage()`), например
  `"r_500", "r_220", "r_35" -> "РНДЗ-220,500.jpg"`.
* В ресурсах всего 7 картинок, и названы они **моделями**:
  `ВВБК-500.jfif`, `ВВБК-220(3 фазы).jpg`, `РНДЗ-220,500.jpg`,
  `АОДЦТН-167000-500-220.jpg`, `ТМ-35.jpg`, `ОПН-220.jpg`, `ТФЗМ-500.jpg`.
* В живой БД 207 единиц оборудования и 25 разных `type`:
  `r_220` (39), `r_500` (25), `Buildings` (14), `tt_500` (11), `MO` (10),
  `shkaf` (10), `tt_220` (10), `v_220` (10), `r_35` (9), `v_500` (9),
  `autotransformer` (7), `opn_500` (7), `s` (7), `ks_220` (6), `tn_500` (6),
  `compressor` (4), `ls` (4), `opn_220` (3), `reactor_500` (3), `tn_220` (3),
  `tsn` (3), `ks_500` (2), `tt_35` (2), `v_35` (2), `opn_35` (1).

Проблема: «ВВБК-220» и «ВВУ-35» — это разные **типы** одного «оборудования»
(выключателя), но сейчас они либо сваливаются в один `v_220`/`v_35`, либо
плодят записи справочника, и фото приходится подбирать по классу.

## 2. Предлагаемая модель

Два уровня:

1. **Оборудование (категория)** — общее название с классом и напряжением:
   «Выключатель 500 кВ», «Разъединитель 220 кВ», «Трансформатор тока 500 кВ»,
   «ОПН 35 кВ», «Здание», «Мачта освещения»…
2. **Тип (модель)** — конкретное изделие: «ВВБК-500», «ВВБК-220», «ВВУ-35»,
   «РНДЗ-220», «ТФЗМ-500», «ТМ-35»…

У каждой единицы оборудования: `category_id` + `model_id` (тип может быть не
заполнен — тогда показывается фото категории).

Фото ищется так: **модель** → **категория** → `equipment.jpg` (заглушка).

### Схема БД (v2)

```sql
CREATE TABLE equipment_categories (
    id          TEXT PRIMARY KEY,      -- cat_breaker_500
    name        TEXT NOT NULL,         -- «Выключатель 500 кВ»
    letter      TEXT,                  -- 'В' — для метки на схеме
    photo       TEXT,                  -- картинка категории (необязательно)
    sort_order  INTEGER NOT NULL DEFAULT 0,
    created_at  INTEGER
);

CREATE TABLE equipment_models (
    id          TEXT PRIMARY KEY,      -- model_vvbk_220
    category_id TEXT NOT NULL REFERENCES equipment_categories(id),
    name        TEXT NOT NULL,         -- «ВВБК-220»
    photo       TEXT,                  -- файл в images/ (или ресурс JAR)
    sort_order  INTEGER NOT NULL DEFAULT 0,
    created_at  INTEGER
);

ALTER TABLE equipment ADD COLUMN category_id TEXT;
ALTER TABLE equipment ADD COLUMN model_id    TEXT;
```

`equipment_types` остаётся как есть, `equipment.type` — legacy-поле
(заполняется `category_id`), чтобы можно было откатиться на старую версию.

## 3. Перенос существующих данных

* Каждый из 51 ключа справочника становится **категорией** с тем же
  `display_name` и `letter` (названия уже почти в нужном виде).
* Для картинок создаются **модели по умолчанию** и привязываются к категориям,
  чтобы фото не пропали ни у одной единицы:

| Категория (было) | Модель по умолчанию | Фото |
|---|---|---|
| Выключатель 500 кВ (`v_500`) | ВВБК-500 | `ВВБК-500.jfif` |
| Выключатель 500 кВ элегаз (`v_500_ABB`) | В-500 элегаз | — |
| Выключатель 220 кВ (`v_220`) | ВВБК-220 | `ВВБК-220(3 фазы).jpg` |
| Выключатель 35 кВ (`v_35`) | ВВУ-35 | — |
| Разъединитель 500 кВ (`r_500`) | РНДЗ-500 | `РНДЗ-220,500.jpg` |
| Разъединитель 220 кВ (`r_220`) | РНДЗ-220 | `РНДЗ-220,500.jpg` |
| Разъединитель 35 кВ (`r_35`) | РНДЗ-35 | `РНДЗ-220,500.jpg` |
| Автотрансформатор (`autotransformer`) | АОДЦТН-167000-500-220 | `АОДЦТН-167000-500-220.jpg` |
| ТСН (`tsn`) | ТМ-35 | `ТМ-35.jpg` |
| ТТ-500 (`tt_500`) | ТФЗМ-500 | `ТФЗМ-500.jpg` |
| ОПН 220 кВ (`opn_220`) | ОПН-220 | `ОПН-220.jpg` |

Остальные категории (ТН, КС, реактор, мачта, здание, шкаф, ЛС, С, компрессор…)
получают модель без фото — сработает заглушка `equipment.jpg`.

* Всем существующим записям: `category_id` = старая категория,
  `model_id` = модель по умолчанию этой категории (если она есть).
* Миграция выполняется автоматически при открытии БД версии 1, с бэкапом в
  `backups/model-v2-<дата>/` и печатью отчёта в консоль.

## 4. Что меняется в интерфейсе

**Карточка оборудования**
* два поля вместо одного: `Оборудование` (ComboBox категорий) и
  `Тип` (редактируемый ComboBox: список моделей выбранной категории +
  возможность вписать новую — она создастся в справочнике);
* картинка берётся по модели, при отсутствии — по категории;
* при смене категории список типов перефильтровывается.

**Справочник** («Управление типами» → «Оборудование и типы»)
* слева категории, справа модели выбранной категории;
* добавить/переименовать/удалить (с проверкой, что не используется);
* для модели — кнопка «Фото»: выбрать файл, он копируется в `images/`
  каталога данных и записывается в `equipment_models.photo`.

**Список оборудования / отчёты**
* колонки «Оборудование» (категория) и «Тип» (модель);
* фильтр и группировка — по категории.

## 5. Порядок работ

1. `Database`: таблицы, CRUD категорий и моделей, миграция v1→v2, тесты.
2. `EquipmentCatalog` (замена `EquipmentTypes`): категории + модели, кэш,
   поиск фото.
3. Карточка оборудования: два поля, сохранение, фото по модели.
4. Справочник: двухуровневый редактор + загрузка фото модели.
5. Список, отчёты Excel, печать: колонки «Оборудование»/«Тип».
6. Миграция живых БД (с бэкапом), проверка на реальных данных.

## 6. Вопросы перед реализацией

1. Категории формируем из текущих 51 ключа (как в таблице) — или нужен свой
   список названий? Например, оставить «В-500» или переименовать в
   «Выключатель 500 кВ»?
2. Напряжение — часть категории («ОПН 220 кВ») или отдельное поле
   (`класс=ОПН`, `напряжение=220`)? Предлагаю первое: проще и понятнее в списках.
3. Тип — свободный текст с автодополнением (создаётся на лету) или строгий
   справочник, где новые типы добавляются только в редакторе?
4. Фото привязываем к типу с откатом на категорию — подтверждаешь?
